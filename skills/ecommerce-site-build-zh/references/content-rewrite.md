# 可选阶段：产品内容迁移与文案重写

用户要求重写产品描述、统一术语或整理产品页内容时启用。它和页面设计并行走同一套闸门：

- "立标准"在 G1 前后完成；
- 3 个试点产品就是 G3 的样板产品页；
- 批量重写在 G4 定稿后和页面铺开一起做。

## 1. 先立标准再动笔

- **找权威依据**：行业标准、官方术语表、品牌自己的用语表。没有就和用户一起建。
- **做一次同行词频核对**：抽取目标市场同品类英文卖家的产品页，统计常用描述词，看哪些说法是行业通用、哪些是生硬直译或借用别的行业（比如用葡萄酒词描述茶）。
- **沉淀成规则表**，每条规则写清：

  | 禁用 | 改成 | 原因 | 例句 |
  |---|---|---|---|

  原因很重要，下次遇到表里没有的词才能举一反三。
- **常见的通用规则**：删掉 perfect / ultimate / amazing 这类空洞夸张词；删掉无法证实的功效和认证说法；同一个概念全站只用一种写法。

## 2. 试点 3 个产品

- 选有代表性的 3 个，给出**逐句 before / after 对照**。
- **等用户确认后再批量。** 这是整个流程最容易跳过、跳过后返工最大的一步。

## 3. 批量 + 回读核对

- 改前备份所有原文；改后逐个读回比对；只改规则覆盖的部分。
- **文本变换用程序做**（替换、解析 HTML），不要让模型重新打一遍全文：重打会引入错别字（实际出现过把"感恩"打成"感慩"）。
- **清理规则写得太宽会误删正文**（实际出现过删图注时把正文一句一起删了），所以每条清理规则先在试点上看 diff。
- 过程中发现的事实问题（年份矛盾、数字可疑、名字写法不一）**只列清单**，交给用户决定。

## 产品页内容结构化

- **描述只放文字**，描述里的图片移到产品图库。移之前先去重：只比感知哈希会漏掉裁剪图和加框的图，要用特征点匹配 + 人工看缩略图确认。
- **可复用内容做成结构化数据**，不要粘贴进每个产品的 HTML：
  - **博主测评**：metaobject（博主、形式、标题、链接、摘要、日期、图片）+ 产品 metafield 引用，由模板统一渲染。YouTube 用普通懒加载 iframe，不用自动播放的"轻量外壳"（在部分环境会显示 Video unavailable）。
  - **规格参数、产地、认证**：metafield，这样同时能用作分类页筛选器。
- **关联关系要精确**：同一个测评视频只挂到真正对应的产品上（例如只挂生茶，不挂同系列的熟茶和拼配款），挂之前把要挂的产品清单给用户过目。
